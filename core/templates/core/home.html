One API, two databases

The same small Pokedex API is served twice: once from PostgreSQL through Django's ORM, and once from MongoDB through PyMongo. The URLs, inputs and JSON responses are identical, so we can compare data modelling, queries, ease of use and speed fairly.

Endpoints (same for both backends)

MethodPath (after /api/sql/ or /api/mongo/)What it does
GETpokemon/List with filters: type, search, min_attack, ordering, limit, offset
GETpokemon/<id or name>/One Pokemon with types, abilities and stats
GETtypes/Each type and how many Pokemon have it
GETstats/by-type/Average stats per type (aggregation)
GETstats/top/?stat=attack&limit=10Highest values for one stat
GET, POSTteams/List teams, or create a team of up to 6 Pokemon
GET, PUT, DELETEteams/<id>/Read (with a join), replace or delete a team

Every response has an X-DB-Time-ms header showing the time spent in the database layer. /api/health/ reports both connections as JSON.
